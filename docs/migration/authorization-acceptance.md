# 权限与撤权验收

日期：2026-09-11。范围为 SaaS 底座，使用自动创建和删除的 `kerthus_test_*` MySQL 数据库；未修改 `beehive_saas`、`kerthus_saas` 的业务数据。

## 本轮修复

网关原来根据 `Auth.roles` 是否包含字符串 `admin` 决定是否跳过精确 HTTP method/path 权限检查。角色代码与平台身份是不同概念：普通租户中同名角色不能代表平台管理员。新增的网关回归测试在修复前失败，确认这一判断会跳过 `CheckAccess`。

现在 RPC `AuthReply.platform_admin` 由服务端账号的 `PlatformAdmin` 属性产生，网关以该布尔字段判定平台能力，角色列表不再参与服务端特权判断。原前端使用的 `admin` 角色名称仅保留给平台账号，普通租户的同名代码对外映射为 `tenant:admin`；租户数据库中的角色代码不作改写。

新增 protobuf 字段默认 `false`，旧服务未返回该字段时不会获得平台豁免。发布时需同步升级 SaaS 服务与 gateway。

## 新增验收

- 普通租户角色名为 `admin` 时，仍需执行精确接口授权，并且不能访问全局账号列表；明确的平台身份仍可通过目标租户参数执行管理查询。
- 全局账号停用会使已有的两个租户会话同时失效；重新启用账号不会复活原会话，新会话可继续使用。
- 通过成员、角色、租户的实际停用命令立即阻断原 token 的相关操作，同一账号在其他有效租户的权限不受影响。
- 解绑角色后原 token 立即失去相应操作；恢复角色关联后重新按当前策略获得权限。
- 撤销租户应用开通后原 token 立即失权；重新开通应用不会自动恢复已删除的角色授权。
- 应用停用后，原 token 的应用操作被拒绝且应用从切换列表消失；独立的基础管理应用仍可访问。应用重新启用后按当前开通和角色策略恢复访问。

运行证据：`go test -race ./internal/gateway/...` 全部通过；`python3 scripts/test-integration.py` 全部通过，SaaS core 用时约 63 秒。已有跨租户读写、最后管理员并发保护、资源与开通交集、过期、范围计算和事务回滚测试一并通过。

这些 SQL 测试使用内存会话端口，验证的是核心授权和版本判定；它们不替代真实 Redis、RPC、浏览器完整链路验收。基础管理列表仍采用此前明确的租户管理面语义，不按个人或部门进一步过滤；后续业务应用需落实 `CheckAccess` 返回的数据范围。

## 管理列表筛选补齐

复用前端中的姓名与手机号输入分别传递 `name`、`phone`。此前 gateway 丢弃 `phone`，通用 `keyword` 也只查询姓名。现在姓名与手机号分别进行字面子串匹配，两者同时输入取交集；通用关键词匹配姓名、手机号或邮箱。SQL 的 `%`、`_` 按输入字符处理，不允许用户输入扩大为通配条件。

成员、岗位列表的组织树传递 `org_id`、`with_child`。现在 `org_id` 限制为目标租户中的节点，包含下级时由服务端读取该租户组织树计算子节点；客户端传递的 `children_ids` 不参与授权或过滤范围。身份筛选、组织筛选、角色关联筛选先求交集，再执行分页与总数统计。一个成员归属多个选中组织时不重复返回。

新增 `query_acceptance_test.go` 和 gateway `query_test.go` 验证完整/部分手机号、姓名与手机号组合、跨租户手机号不泄露、邮箱关键词、字面通配字符、角色与组织交集、直属与递归组织、空组织、多组织去重，以及成员/岗位的分页总数。

## 展示 DTO 补齐

用户、岗位、应用开通 DTO 补齐 `created_at`、`updated_at`，供现有成员/用户/岗位列表显示创建时间、应用授权列表显示授权时间。员工列表保持旧项目语义，显示账号创建时间。当前角色页面没有时间列，未增加对应字段。

用户列表、成员列表/详情和个人资料响应显式返回 `sex: 0`，避免 protobuf 的零值省略使编辑表单把“未设置”误当成缺少字段。`dto_test.go` 验证这些 HTTP 响应；`dto_acceptance_test.go` 验证数据库时间被传回 DTO，且新增/修改实体时客户端提交时间字段不能覆盖服务器维护的时间。
