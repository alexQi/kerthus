# SaaS 基础底座验收

2026-09-11。本轮落实原账号兼容、租户权限隔离、复用管理台的基础管理操作；不新增业务应用。

## 本轮结果

### 原账号与数据

当前服务继续使用从本机 `beehive_saas` 转换的 `kerthus_saas`。62 个账号、45 个租户的身份、成员关系、状态和期限已只读核对；没有重置真实密码或修改原库。迁移 005 和单字段补齐已保留原单会话策略：61 个开启，1 个关闭。

旧摘要验证成功后事务性升级 bcrypt；单会话账号的新登录撤销旧会话，多会话账号保持并存。错误密码不撤销现有会话，并发密码升级不能覆盖改密、停用或撤销后的状态。手机号、邮箱、重复邮箱拒绝歧义均有独立 SQL 回归。

重启后的真实 HTTP → go-micro RPC → MariaDB 链路再次返回 62 个账号、45 个租户、5 个应用目录，平台身份和账号时间字段正确；旧数据集的 Redis 会话不能进入当前数据集。诊断会话已删除。测试没有使用用户的真实密码，不能据此宣称原账号密码已人工登录验收。

### 权限与列表

平台管理员以服务端账号身份字段判定，前后端均不再把角色名称 `admin` 当作平台特权。成员、角色、租户、账号、应用停用及解绑/撤销授权，会按当前状态拒绝原 token 的相应操作；无关租户或应用不受影响。

姓名、手机号和关键词筛选已对齐旧表单；组织及下级范围由服务端按目标租户计算，先过滤再分页。创建时间、性别零值等 DTO 已补齐。新清单与原权限代码的状态按钮兼容；未给迁入账号扩大授权。

### 复用管理台

- 租户创建、编辑、审核可完整执行；空 LOGO、无限有效期及审核密码输入正确处理。
- 指定租户中的成员新增、编辑、停用保持目标租户，重新打开表单不会加载平台组织；空邮箱、未设置性别可兼容原账号。
- 全局账号编辑实际持久化；租户成员入口兼容新旧动态路由。
- 组织连续保存更新同一条记录；岗位和角色新增、编辑、停用、删除通过真实接口验收。
- 角色资源在切换角色/页签时正确回填，全选可保存，已有数据范围保留，新授权默认个人范围；租户应用保存保留开通期限，排除平台及已停用应用。
- 确认框异步提交、失败后重试、取消、销毁和密码重置可正常关闭；修复旧静态弹窗在当前 Vue/Ant Design Vue 组合下更新不生效的问题。
- 会话过期只清理一次，不再递归调用退出接口；迟到的旧请求不会清除新登录。

## 验证方式

| 检查 | 结果与范围 |
| --- | --- |
| `make test` | Go 单测、vet、应用依赖边界通过 |
| `make integration` | 随机 MySQL 测试库，race 回归通过，包含旧密码/单会话、撤权、跨租户、筛选及 DTO |
| `yarn type:check`、`yarn build` | Vue 类型检查和生产构建通过 |
| `make smoke-crud` | 10 组真实浏览器基础管理流程通过，页面异常和失败接口均为 0 |
| `make smoke-grants` | 6 组资源/数据范围/应用期限流程通过 |
| `make smoke-approval` | 审核输入、取消重开、短密码校验和成功关闭通过 |
| `make smoke-dialogs` | 9 组弹窗、应用切换及真实密码重置流程通过；短密码请求的 400 是预期校验 |
| `make smoke-session` | 并发 401、错误密码、迟到请求、重复退出及平台身份判断通过 |

浏览器 CRUD/授权/审核/弹窗脚本通过 `test-browser-crud.py` 使用随机测试库、私有 go-micro 注册表和独立 Redis 会话命名空间，浏览器 API 只转发到测试服务，结束后清理数据库及会话。需要先运行管理台开发服务；Playwright 可安装到环境或用 `KERTHUS_PLAYWRIGHT_PATH` 指定模块位置。会话脚本使用隔离响应，不需要数据库。

## 当前边界

原租户的停用、到期状态及历史应用开通范围保留。44 个普通租户原本仅开通本轮未迁移的 noctua，未自动授予 basic 管理权限；这些账号没有基础应用入口是数据和授权现状，不应通过放宽鉴权解决。

当前登录密码长度上限为 72 字节，开户和新密码要求 10–72 字节。旧算法本身可以处理更长密码；若原账号确实使用超过 72 字节的密码，当前登录入口不能兼容，需另行处理，不能由摘要核对推断密码长度。

基础管理列表采用租户管理面语义；后续业务应用需执行 `CheckAccess` 返回的数据范围。旧头像/LOGO 保留原地址映射，原对象文件未搬迁。完整数据转换记录见 [沿用本地数据](legacy-data-import.md)，权限细节见 [权限与撤权验收](authorization-acceptance.md)，后续独立应用按 [应用接入说明](../architecture/application-onboarding.md) 接入。
