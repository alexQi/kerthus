# SaaS 底座浏览器验收清单

整理于 2026-09-11。本清单是当前源码、fresh 应用清单和旧目录导入规则的只读盘点，供内置浏览器逐页验收使用，**不是已通过记录**。未访问数据库、未读取真实凭据、未操作浏览器。实际修复和视觉结果以本轮主验收记录为准。

## 页面与行为矩阵

风险：R＝只读；W＝写入业务数据；A＝变更身份、权限、密码或会话。W/A 应使用独立验收租户、成员、应用和资源；保留原数据的真实页面用于只读回归。每个列表共同检查：筛选、重置、分页、刷新、列设置、空数据、加载失败、横向滚动；每个表单共同检查：必填、取消重开、编辑回填、重复点击、成功关闭、错误后可重试。

## 旧目录与 fresh 清单差异

- fresh 路由的确定来源是 `applications/system/app.yaml`、`applications/basic/app.yaml`，共有 14 个 view（含隐藏租户详情/开通应用）。公共个人中心由权限 store 追加。
- 旧导入规则保留合法的原 `path/component/code`，不把它们重命名为 fresh 路径。已知兼容跳转示例：租户列表旧 `/system/tenant/index`、fresh `/system/tenants`。其他旧地址不能仅由文件名推定，应通过当前浏览器菜单逐页进入并记录。
- `internal/platform/legacy/catalog.go` 明确停用 `system:log`、`system:log:*`、`basic:rcc*` 和未迁移业务应用资源。`system/log/main/index.vue` 是旧占位模板但不在已支持目录，不能将其当成当前审计页。
- 旧导入可复用 `basic/application/main/index`（租户应用详情），fresh 无该入口；fresh 有 `/basic/audit`，不应假设旧目录已获得新的审计资源授权。
- `common/about`、iframe 和 dashboard 内未引用统计组件的文件存在不代表可达。是否进入“所有功能”应以当前有效目录、公共路由及可见入口为准。

## 代码盘点发现（修复前快照，待主验收逐项核验）

1. **个人资料部分保存存在数据破坏/拒绝风险。** `BaseSetting.handleSubmit` 只提交表单字段，而 `core.saveUser` 完整赋值 `Avatar/Sex`，会把未提交值覆盖为空/0；头像上传只提交 avatar，但后端要求姓名，可能直接失败。非平台账号修改邮箱要求当前密码，UI 无该输入。简介和所在地区输入没有对应 User 合同/持久化字段，保存成功也不会保留。
2. **安全设置展示假值及无效动作。** `profile/data.ts` 固定展示 `138****8293`、`ant***sign.com`、“密码强度强”；`SecureSetting` 只有密码分支执行，其余修改按钮没有行为。第三方绑定按钮无 click，通知开关仅本地 default-checked。应以真实能力和状态展示，不能静默假成功。
3. **锁屏账号密码备用解锁使用了昵称。** `store/modules/lock.ts` 的 phone 场景登录 username 来自 `getUserInfo.name`，与手机号登录契约不符。自设锁屏密码路径不受这一点影响。
4. **授权列表按钮权限写反。** `system/application/authorize/index.vue` 工具栏“取消授权”使用 `...:auth`，“授权”使用 `...:deauth`；行内撤权使用 deauth。非平台受限角色下可能呈现错误动作。
5. **资源管理可用性待重点复现。** `resource/tree.vue` 的应用搜索匹配 value（ID）而非 label（应用名），空应用时直接读 `tempVal[0].value`；`resource/form.vue` 多处 resetFields/setFieldsValue 未按顺序 await，存在编辑回填被清空风险。`resource/index.vue` handleEdit 通过 toggle 编辑态，连续点不同节点可能误关编辑。
6. **应用详情契约/回填待复现。** basic 与租户详情两份应用 detail 直接 `is_public.toString()`，对省略0/null字段不稳健，reset 和回填也未 await。需验证私有应用、多次打开不同记录以及长详情布局。
7. **文字准确性。** 应用管理和租户应用授权表格 title 都是“租户列表”。顶部帮助按钮固定打开旧项目语雀链接，需确认其仍是当前底座说明。
8. **通知状态说明。** 当前活跃 `tabListData` 的通知/消息/待办均为空；演示条目在未引用的 `tabListDataBack`。因此不是当前显示假通知，而是尚无通知后端接入。不可将空列表宣称为已完成通知系统。

## 视觉验收建议顺序

先真实旧目录只读走通工作台、每个有效菜单、列表和详情，记录长中文名称/空字段/零时间/头像等实际视觉效果；再隔离验收身份跑增改删、密码和授权；最后使用普通租户成员验证菜单按钮权限、401/403、无应用空态，并回真实账号确认原数据未变化。每一大类至少保留一张清晰截图，异常需有复现动作和修复后截图；静态盘点或自动化脚本不能替代本轮要求的内置浏览器视觉验收。
